# Uganda Geo v2.0.1: Memory and property-based qualification

These two workstreams belong to the **single, unreleased v2.0.1 core overhaul** in PR #63. They neither introduce Laravel integration nor change historical source identities.

## Memory methodology

We profile memory in fresh PHP processes instead of accumulating unrelated benchmarks in one long-lived process.

- `memory_get_usage(false)` measures currently allocated PHP-managed memory.
- `memory_get_usage(true)` measures pages reserved by the PHP allocator, including unused pages.
- `memory_get_peak_usage(false|true)` captures the corresponding peaks.
- Neither measurement is a complete operating-system RSS or native-extension allocation profiler.

This distinction matters: an allocator can retain reserved pages after PHP objects have been released. A reserved-memory plateau is not itself evidence of a live-object leak.

References: [PHP memory_get_usage](https://www.php.net/manual/en/function.memory-get-usage.php) and [PHP memory_get_peak_usage](https://www.php.net/manual/en/function.memory-get-peak-usage.php).

### Profiled workloads

| Scenario | Purpose |
| --- | --- |
| `construct` | Baseline immutable snapshot construction, then three stable observations |
| `full-index` | Force each level's ID index plus global name and prefix indexes |
| `cache-churn` | Repeated scoped names, prefixes and ancestry for 1,500 village queries |
| `stream` | Traverse the village dataset without creating a flattened result array |
| `flatten` | Allocate and release a complete village collection repeatedly |
| `instance-churn` | Construct and release 12 independently hydrated geography engines |

Use `php -d memory_limit=128M tools/benchmarks/memory-profile.php cache-churn 1500` to reproduce a workload. For object lifetimes, use `php -d memory_limit=128M tools/benchmarks/instance-churn.php 12`.

### Enforced bounds

- PHP allocator peak **at most 128 MiB** across each workload.
- Second-pass additional *active* allocations **at most 8 MiB**, verified against the underlying samples.
- Post-disposal retained active allocations **at most 4 MiB** across independent engine instances.
- No zero-record scenarios or fabricated profiler reports pass the gates.
- Existing bounded ancestry and scoped-name caches remain limited to 512 and 256 entries respectively.

The [bounded memory workflow](../../.github/workflows/memory-profiling.yml) runs on PHP 8.2, 8.4 and 8.5. It uploads each scenario's complete metrics as CI artifacts. These budgets are deployment-specific guardrails, not an impossible-to-exceed theoretical bound or a universal OS memory measurement.

## Deterministic generated properties

The property suite uses an independent Park-Miller seeded fixture generator. All seeds are reproducible without modifying PHP's global random state or requiring an additional runtime package.

1. **96 generated hierarchies:** exact IDs, case-normalized names, parent scopes and invalid IDs match a reference oracle.
2. **64 generated hierarchies:** lexicographic prefix search, duplicates, limits and both index-warmup orders match the oracle.
3. **96 generated hierarchies:** all administrative child and ancestry relationships plus lazy streaming preserve identities.
4. **40 randomized mixed workloads of 400 operations:** query order never changes results or defeats cache-entry bounds.
5. **128 corrupted-record mutations:** malformed IDs, names and parent references fail closed.
6. **96 orphan-link mutations and 60 duplicate-ID mutations:** no partial or silent hierarchy attachment.
7. **72 JSON serialization seeds:** flat identity contracts remain correct without recursive output, while nested `toArray()` remains available.
8. **Independent negative tests:** malformed UTF-8, invalid JSON collections, nonpositive prefix limits, nonnative IDs and invalid benchmark reports.

When a generated assertion fails, the failure message includes the seed, hierarchy level and relevant query details. Re-running the named PHPUnit test recreates the same sequence of fixtures.

The [property regression workflow](../../.github/workflows/property-regressions.yml) runs these checks on PHP 8.2, 8.4 and 8.5, in addition to the complete PHPUnit matrix.

### Reproducing the gates

```bash
composer install
./vendor/bin/phpunit --no-coverage --filter 'Property|Mutation|Churn|Budget|Fingerprint|CacheBound'
php -d memory_limit=128M tools/benchmarks/memory-profile.php full-index 3
php -d memory_limit=128M tools/benchmarks/instance-churn.php 12
```

Passing these defined scenarios is a **bounded engineering qualification**, not proof that every future workload is impossible to optimize. Unicode-aware fuzzy search is documented and verified independently in [the Unicode and fuzzy qualification](v2.0.1-unicode-fuzzy-qualification.md). The final independent PR review remains a distinct v2.0.1 release gate.
