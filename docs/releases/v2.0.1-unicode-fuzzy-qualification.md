# Uganda Geo v2.0.1: Unicode-aware and fuzzy location search

This design is part of the single v2.0.1 patch candidate. Unicode search is **opt-in**: the existing `searchByName()`, `searchByPrefix()` and singular location methods retain the v2.0.0 ASCII semantics, source model objects and warm-path performance.

## Extension compatibility and explicit contracts

The production package still requires only PHP 8.2+ and `ext-json`. Advanced Unicode and fuzzy APIs additionally require the **optional** PHP `ext-intl` extension. If it is absent, an explicit `RuntimeException` explains the missing capability. Ordinary location traversal and legacy search continue to work without `intl`.

The new query names are:

| Public method | Returns | Behavior |
| --- | --- | --- |
| `searchByUnicodeName($level, $name, $parentId = null, $ignoreDiacritics = false)` | Original models | Canonical and compatibility Unicode name equivalence |
| `searchByUnicodePrefix($level, $prefix, $parentId = null, $limit = null, $ignoreDiacritics = false)` | Original models | Unicode-normalized prefix matches in deterministic key order |
| `searchFuzzy($level, $query, $parentId = null, $limit = 10, $maxDistance = 2, $ignoreDiacritics = false)` | Original models | Ranked typo and adjacent-transposition suggestions |
| `searchFuzzyWithScores(...same arguments)` | `[{unit, distance}, ...]` | Exact same ranking with an explicit integer edit count |

**Example:**

```php
<?php

use Uganda\Uganda;

$geo = new Uganda();
$canonical = $geo->searchByUnicodeName('district', 'ＭＵＫＯＮＯ');
$prefixes = $geo->searchByUnicodePrefix('parish', 'caf', null, 10, true);
$suggestions = $geo->searchFuzzyWithScores('village', 'kampalaa', null, 10, 2);

foreach ($suggestions as $suggestion) {
    echo $suggestion['unit']->id() . ': '
        . $suggestion['unit']->name()
        . ' (' . $suggestion['distance'] . ' edits)' . PHP_EOL;
}
```

The example queries are illustrative. Whether a given name exists depends on the bundled source snapshot.

## Unicode semantics

- ICU `Normalizer::FORM_KC_CF` implements Unicode NFKC case folding. It handles canonical equivalents, compatibility variants and full case folding across scripts.
- Unicode whitespace separators are collapsed to spaces and surrounding whitespace is removed.
- Diacritic removal is **disabled by default**. `$ignoreDiacritics = true` removes combining marks after NFD decomposition, then recomposes the normalized key.
- Unicode regex `\\X` segments extended grapheme clusters. An emoji sequence or a base letter with combining marks is treated as one fuzzy-search unit.
- Edit distance uses **optimal string alignment (OSA)**, a restricted Damerau–Levenshtein algorithm with adjacent transpositions. It is not unrestricted Damerau distance or phonetic matching.
- Fuzzy rankings are ascending edit count then ascending normalized name bytes. Ties between duplicate names preserve original source ordering. This does not depend on locale-specific collation.
- Every result is an original source model. Equivalent spellings **never collapse different source IDs into one location**.

Do not use Unicode/fuzzy matches for authorization or for automatically selecting a unique administrative identifier. NFKC normalization is not UTS #39 visual-confusable detection; visually similar mixed-script text may remain distinct. Present ambiguous results for explicit selection.

## Bounds and performance architecture

- `$limit` for fuzzy search must be 1–100.
- `$maxDistance` must be 0–3. Zero is an exact Unicode-normalized match.
- Query length cannot exceed 128 grapheme clusters or 4,096 original UTF-8 bytes.
- Invalid UTF-8 and empty normalized queries fail with `InvalidArgumentException`.
- Normalized dictionaries are built lazily for the requested administrative level and diacritic mode. An LRU retains at most two indexes.
- Parent-scoped exact, prefix and fuzzy queries scan the parent's canonical immediate children without constructing a national name dictionary.
- Global prefix queries use a sorted-name binary search. Fuzzy global queries use grapheme-length buckets and a **necessary multiset histogram bound** before the full edit-distance algorithm.
- The histogram has 41 exact ASCII buckets and 32 hashed Unicode grapheme buckets. Hash collisions can admit extra candidates but can never reject a valid OSA match.
- No FTS database, search daemon or persistent index is required. All indexes are process-local and optional.

### Complexity expectations

| Operation | First use | Warm path |
| --- | --- | --- |
| Global exact Unicode name | O(N) normalization and index construction | Average O(1 + returned matches) |
| Scoped exact Unicode name | O(children of parent) | O(children of parent) |
| Global Unicode prefix | O(N) indexing plus O(U log U) sorting | O(log U + returned candidates) |
| Scoped Unicode prefix | O(C log C) worst case | O(C log C) worst case |
| Global fuzzy | O(N) dictionary/length/signature preparation | Length-bucket scan plus bounded OSA checks on survivors |
| Scoped fuzzy | O(children of parent) plus bounded OSA | No global dictionary required |

Here N is the number of locations, U is the number of unique names and C is the size of an immediate parent-child collection. Fuzzy time is workload-dependent; there is no universal nanosecond guarantee.

## Verification and benchmarks

The dedicated `.github/workflows/unicode-search.yml` runs Unicode tests with `ext-intl` on PHP 8.2–8.5 plus a separate PHP `-n` check of legacy no-intl operation. It checks strict PHPStan analysis and eight real-dataset query profiles. The existing v2.0.1 matrix continues to guard the legacy path.

Use:

```bash
composer install
./vendor/bin/phpunit --no-coverage --filter 'Unicode|Fuzzy'
php tools/benchmarks/unicode-search.php fuzzy_global 20
php tools/benchmarks/unicode-search.php fuzzy_unicode_global 20
```

The profile reports first use, warm p50/p95/p99, fingerprint stability and peak PHP allocator reservation. `verify-unicode-budgets.php` independently validates the results and enforces bounded budgets. Tests include independent OSA reference matrices, seeded geography oracles, cross-script security cases, invalid UTF-8, source-ID preservation and candidate-filter completeness.
